# Finding categories

The starting vocabulary for a run record's `category` (see `DESIGN.md`). A category is the unit a retro counts, so the same mistake must get the same name in every run. Before inventing a category, reuse one from this catalog, the rules ledgers, or earlier run records; invent a new kebab-case one only when none fits, and name the kind of mistake, not the incident. A retro may propose adding a recurring new category here, as a framework-scope proposal behind the human gate.

Each entry: the category, what goes wrong, the `stage` where it is usually made (the run record's `stage`: where the mistake was made, not who caught it; the lead's own mistakes, preflight included, are `plan`), and the cheapest rule known to stop it. A rule naming a part of this plugin (a gate, a preflight step, an agent's standing check) is already applied there; the others are what a retro should propose when the category recurs.

## Process

| Category | What goes wrong | Usually made | Cheapest known rule |
|---|---|---|---|
| `skipped-plan-approval` | Implementation started, or was committed, before a plan that needed the human's approval was approved (in a delegated run, the human's answer relayed by the delegator; an agent's approval never counts). | plan | Gate: `scripts/record_gate.py` fails without `plan_approved`, and on commits authored before it (DESIGN.md, "Gates"). |
| `skipped-independent-review` | The change was reported done without an independent review of the final diff (self-review, or fixes made after the last review). | plan | Gate: `scripts/record_gate.py` fails unless the change still matches the fingerprint taken for the last review (`reviewed_diff`). |
| `branch-over-budget` | A unit or branch went well over the branch budget, or was split into a code part and a tests part. | plan | Split by behaviour with tests alongside; the lead checks `git diff --stat` per unit. |
| `stale-trunk` | Branched from, or compared against, a stale local default branch instead of `origin/<default>`. | plan | Preflight: fetch, then branch from `origin/<default>` with `--no-track`. |
| `scope-mismatch` | The change does more or less than the task asked: unrequested changes, or part of the task silently dropped. | implement | Criteria name every requested behaviour and the plan lists what is out of scope; the reviewer's scope and unmet-criteria checks. |

## Generated files

| Category | What goes wrong | Usually made | Cheapest known rule |
|---|---|---|---|
| `generated-artifact-not-regenerated` | A generator's input changed without regenerating its checked-in or CI-used output, so CI or the build breaks. | implement | Preflight finds each generator and its stale-artifact check; the pre-push gate runs them. |
| `new-file-matches-generator-glob` | A new file matched a generator's input glob and silently became, or broke, a generated job or artifact. | implement | Preflight records each generator's globs; every new file is checked against them. |
| `generated-file-hand-edit` | Generated output was edited by hand instead of its source, so the next regeneration loses the edit. | implement | A project hook refusing edits to files headed `Generated by`; the implementer's rule against editing generated files and the reviewer's scope check. |

## Measurement

| Category | What goes wrong | Usually made | Cheapest known rule |
|---|---|---|---|
| `measurement-attribution-leak` | A measurement credits the wrong scope, such as coverage collected during setup or import and given to whichever test ran first. | implement | Invariant: a subset run never beats the full run; count only what runs inside a test body. |
| `shared-state-false-failures` | Tests share state (a database session, a global, a temporary directory), so one failure poisons the rest: a wall of false failures, or a test that fails in the suite and passes alone. | implement | Isolate state per test (roll back per example); in a mass failure, investigate the first failure before believing the rest. |
| `wrong-auth-identity` | A test or check runs as a convenient identity (an admin, a machine token) instead of the role real clients use, so its results do not match theirs. | implement | Test as the real client's role and credentials. |

## Environment

| Category | What goes wrong | Usually made | Cheapest known rule |
|---|---|---|---|
| `shell-portability` | A multi-step command depends on the interactive shell (word splitting, globbing, builtins) and does something else there, such as running a whole suite. | implement | Run multi-step scripts with `bash -c`, or as a file with a shebang. |
| `leftover-resources` | An aborted or finished heavy run left containers, worktrees, temporary databases or processes behind. | test | After any aborted heavy run, remove what it started and check that nothing is left. |

## Security

| Category | What goes wrong | Usually made | Cheapest known rule |
|---|---|---|---|
| `redaction-gap` | A secret-shaped value gets past redaction or sanitising: glued to a neighbour, quoted, split across a boundary. | implement | An adversarial input list and a must-not-match list as acceptance criteria (the lead's plan step). |
| `over-broad-pre-approval` | A permission entry (`allowed-tools`, agent `tools`, settings, CI token) is wider than needed: a wildcard that admits a writing flag, or a path a cloned repo could plant. | implement | The reviewer's standing least-privilege check. |
| `regex-performance` | A regular expression applied to untrusted or unbounded input backtracks badly on adversarial strings. | implement | The tester's standing timing check on 100-200 KB adversarial input. |

## Contract

| Category | What goes wrong | Usually made | Cheapest known rule |
|---|---|---|---|
| `contract-gap` | The contract, plan or brief does not say what an agent needed (an interface, an edge case, a format), so it had to guess. | plan | Agents stop and report a gap or conflict instead of guessing (the implementer's deviations, the test-writer's missing interfaces); the lead fixes the plan. |
| `contract-self-contradiction` | The contract or brief says two incompatible things, so any implementation breaks one of them. | plan | Check each new rule against the existing rules it touches before writing it down. |
| `doc-drift` | A change updated one description of a behaviour (a skill, an agent prompt, the README, the design) and left another saying something else. | implement | Search for every other place that states the changed behaviour and update it in the same change. |
